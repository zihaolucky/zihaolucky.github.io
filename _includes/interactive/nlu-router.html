Interactive — try to tune the cascade

Find the threshold that routes all seven correctly

The industry standard was rules first, then model. Nothing is blended: step 1 checks the hand-written templates, and if a match clears the bar the request is routed there and step 2 never runs at all. The learned model only sees what the rules let through. That leaves one thing to tune — how strong a match has to be before the rule is trusted. Drag it and try to find a threshold where all seven of these real request types land in the right place.

This interactive needs JavaScript. In short: no threshold on match strength routes all seven utterances correctly, because a template can match strongly and still be wrong — and no threshold can tell those two apart. The patented memory network weighs the template evidence per utterance instead.

Illustrative model of the mechanism, not production data — the match scores are simplified so the trade-off is visible in seven cases instead of millions. The production result of replacing the cascade with learned fusion is on the chart further down: ~65% → ~85% domain-classification accuracy, and 35% fewer routing errors from the fusion layer alone.
